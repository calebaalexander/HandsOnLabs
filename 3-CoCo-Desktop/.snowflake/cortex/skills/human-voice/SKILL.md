# Human voice

Rewrite the text the user points to (by default, your last answer) so it reads like a colleague wrote it.

## Steps

1. **Find the audience and the channel.** Use the ones the user named, such as "Slack message to the support lead." If none is named, write a short note to a colleague.
2. **Keep every fact.** Keep every number, name, table, and date exactly as it was. Don't add claims, numbers, or causes that weren't in the original. If the original was unsure about something, keep it unsure.
3. **Lead with the point.** The first sentence says the answer or the ask. Evidence comes next. Then the limitation, then the next step.
4. **Write the way people talk.**
   - Use short sentences and plain words. Use contractions, like "it's" and "we don't."
   - Mix sentence lengths so it doesn't sound like a template.
   - Use "we" and "you," not "the user" or "stakeholders."
   - Use bullets only for three or more parallel items. Don't use headers in anything shorter than a page.
5. **Cut machine habits.** Don't use:
   - Em dashes.
   - Openers like "Great question," "Certainly," or "Let's dive in."
   - Closers like "I hope this helps" or "Let me know if you have any questions."
   - Filler words: delve, leverage, robust, seamless, crucial, pivotal, comprehensive, landscape, "it's worth noting," "in today's world."
   - Three-part lists added only for rhythm.
6. **Fit the length to the channel.**
   - Slack: four sentences or fewer.
   - Email: 150 words or fewer, with a subject line.
   - Exec update: three bullets or fewer.
7. **Return only the rewritten text.** No preamble. After it, add one line, "Changed:", that names anything you dropped or softened, so the user can check it.
